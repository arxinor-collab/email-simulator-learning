# 电子邮箱模拟学习系统

面向特殊教育课堂的电子邮箱模拟练习，包含分层提示、语音播报、答题练习和纯静态 GitHub Pages 版本。

# 贝贝的生日邮件：模拟学习系统

这是一个面向《收发电子邮件》课堂的受控邮箱教学原型。界面沿用真实邮箱的空间语法：顶部导航、左侧“收信/写信”、文件夹列表、右侧邮件内容区。学生沿着“查收—回复—写信—迁移—安全判断”的任务流练习，填写主题和正文，并通过服务端发送给预设的贝贝邮箱。

进入系统后先显示课堂登录页。学生从账号框下拉选择姓名，系统展示对应的英文邮箱账号和打码密码；点击“登录”后进入学习入口。当前名单为小奕、小坚、小宇、朗朗、小仪、小信、喧喧，邮箱后缀为 `example.com`，名单位于 `public/app.js` 顶部的 `studentAccounts` 数组。

登录后的学习入口分为两条路径：

- **课堂练习**：进入五关选择页。教师可以在“老师指令”区域指定任务编号，学生点击对应关卡进入邮箱模拟练习。
- 进入具体关卡后先显示学生个人邮箱主页：头像、姓名和邮箱账号下方只保留“未读邮箱”“联系人邮箱”两个入口；模拟邮箱页面隐藏顶部导航，左侧功能区也只保留这两个入口。
- **课后巩固**：先完成三个步骤的模拟复习，依次复习收件箱位置、回复/写信判断和发送前检查；完成后显示新浪邮箱、QQ邮箱、网易邮箱三个外部跳转按钮，学生可使用自己的邮箱继续实操。

当前前端已经实现制作方案 V1.0 中的主要教学界面：

- 五关任务进度：找到邀请、回复贝贝、主动写信、邮件应用大挑战、查收回信。
- 三档动态支架：A级独立完成、B级关键词提示、C级一步一步提示。
- 多封邮件、发件人/主题/正文提取、错误后的自然反馈与逐步定位。
- 回复/写信功能判断、通讯录选人、发送前检查弹窗和能力结果页。
- 第五关的课堂模拟回信与三个邮箱安全判断情境。
- `/api/events` 只记录受控的学习事件，不记录正文、键盘原始记录或全桌面信息。

当前第五关的回信由课堂流程生成，用于先验证教学交互；真实 SMTP 自动回信服务仍可在此基础上继续接入。

## 可行架构

```text
浏览器邮箱 UI
      │ 只提交 recipientEmail / subject / body / studentId
      ▼
Node HTTP 服务
      ├─ 请求校验与白名单
      ├─ 学生级 + IP 级速率限制
      ├─ 结构化 JSONL 日志
      └─ SMTP 发送器（仅服务端持有密钥）
              │
              ▼
        贝贝唯一邮箱
```

原型支持两种模式：

1. **教学演示模式**：没有完整 SMTP 配置时默认启用。发送动作会经过全部校验，并写入 `data/send-log.jsonl`，但不会向外投递，适合先做界面、流程和教学支架测试。
2. **联网发信模式**：填写完整 SMTP 配置后启用。邮件通过 SMTP 真实发送，收件地址仍由服务端固定为 `BEIBEI_EMAIL`。

## 安全边界

- 收件人由服务端做精确邮箱白名单校验，只允许 `BEIBEI_EMAIL`；前端的锁定显示不构成安全措施。
- 接口不接受抄送、密送、附件或 HTML，只发送纯文本，降低误发和注入风险。
- 每个 `studentId` 10 分钟最多发送 3 封，单个 IP 10 分钟最多发送 20 封；同一学生两次发送至少间隔 20 秒。
- SMTP 用户名、密码和发件地址只读服务端环境变量，绝不返回 `/api/config`。
- 日志只记录请求编号、时间、学生标识、收件地址、主题长度、正文长度、状态和错误代码，不保存正文、密码或原始键盘记录。
- 原型不采集摄像头、麦克风、全桌面录像或课程无关页面数据。操作过程评价宜继续采用“机器记录事实—规则判断关键步骤—教师确认结论”的边界。
- 正式部署应放在 HTTPS 反向代理后，使用专用发信邮箱和专用贝贝收件邮箱，并在课堂前用测试账号完成一次投递测试。

## 启动

需要 Node.js 18 或更高版本。演示模式无需安装第三方包：

```bash
npm start
```

打开 <http://localhost:3000>。

如需真实投递：

```bash
cp .env.example .env
```

编辑 `.env` 中的 `BEIBEI_EMAIL` 和 SMTP 配置，再启动服务。465 端口使用直接 TLS；587 端口可设置 `SMTP_SECURE=false`，服务会先建立连接，再执行 STARTTLS。

默认只监听本机 `127.0.0.1`。需要由反向代理接入时，再把 `HOST` 设置为适合部署环境的监听地址。

## 教学支架

左侧“教学支架”提供三档：

- **完整提示**：显示“找收件人—写主题—写正文—检查—发送”步骤和可插入句式。
- **逐步提示**：保留检查清单，隐藏句式按钮。
- **独立完成**：移除操作提示，只保留必要的收件人锁定和发送结果。

三档都保留同一个核心任务：确认收件人、填写主题和正文、检查后发送。句式按钮只提供输入支架，不替代学生完成邮箱操作。

## 接口

### `GET /api/config`

返回课堂页面需要的公开配置：贝贝姓名、贝贝邮箱、当前是演示模式还是联网模式，以及频控提示。不会返回 SMTP 密钥。

### `POST /api/send`

请求示例：

```json
{
  "recipientEmail": "beibei@example.com",
  "subject": "生日派对",
  "body": "您好，贝贝！我会参加你的生日派对。",
  "studentId": "学生1",
  "sessionId": "class-2026-09-26"
}
```

服务端会重新固定收件人为 `BEIBEI_EMAIL`，所以客户端不能借此接口向其他地址发送。

### `POST /api/events`

用于记录受控的学习过程事件，例如打开哪封邮件、选择了“回复”还是“写信”、使用了哪档支架和安全判断结果。服务端只接受白名单中的事件类型，并过滤未知字段；邮件正文、密码和原始键盘记录不会写入事件日志。
